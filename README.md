# TechFlow — سامانه عملیات و پایش تیم فناوری

TechFlow یک سامانه یکپارچه برای **مدیریت عملیات، پایش وضعیت، و شفاف‌سازی تصمیمات** در تیم فناوری است.
هدف آن جایگزینی «تابلوهای پراکنده + پیام‌های واتس‌اپ + حافظه جمعی» با یک منبع واحد است؛ به‌گونه‌ای که
مدیر تیم، اسکرم مستر، توسعه‌دهنده و معاون فناوری هرکدام **پیشخوان مناسب نقش خود** را ببینند.

## ویژگی‌های کلیدی

- **پیشخوان‌های نقش‌محور** — چهار نمای متفاوت: توسعه‌دهنده، مدیر تیم، اسکرم مستر، معاون فناوری.
- **پروژه‌ها با سیگنال ریسک شفاف** — ریسک هر پروژه (در مسیر / در معرض ریسک / مسدود) از داده محاسبه
  می‌شود (تاریخ اتمام، مانع باز، به‌روزرسانی ضعیف) نه از قضاوت سلیقه‌ای.
- **تغییر اولویت با ردپای کامل** — هر تغییر اولویت با دلیل، اثر و تغییردهنده ثبت می‌شود.
  مجوز: مدیر تیم، مدیر سیستم و **معاون فناوری**.
- **موانع (Blockers) به‌عنوان داده یک‌درجه** — ثبت ۳ کلیک، نمایش برجسته روی داشبوردها.
- **پشتیبانی به‌عنوان دسته‌ی کاری** — تیکت‌ها بدون ساعت‌شماری؛ فقط وضعیت، شدت و زمان‌بندی.
- **ظرفیت بر مبنای درصد** — بدون تایم‌شیت؛ بیش‌تخصیص/کم‌تخصیص به‌صورت هشدار نمایش داده می‌شود.
- **کارهای ورودی** — کارهای غیربرنامه‌ای ثبت و سپس به وظیفه/تیکت/پروژه تبدیل می‌شوند.
- **گزارش هفتگی** — خروجی آماده برای مدیریت: پیشرفت، موانع، بار پشتیبانی، تغییرات اولویت.
- **گزارش وقایع (Audit)** — چه کسی چه چیزی را چه زمانی تغییر داد.
- **RBAC کامل** — دسترسی‌ها در لایه API اعمال می‌شود؛ UI فقط نمایشگر است.

## ساختار راه‌اندازی

| لایه      | فناوری                    | آدرس                                       |
| --------- | ------------------------- | ------------------------------------------ |
| دیتابیس   | PostgreSQL (لوکال/Docker) | `localhost:5432` (لوکال) / `5433` (Docker) |
| بک‌اند    | Django 5 + DRF            | `http://localhost:8000`                    |
| فرانت‌اند | React 18 + Vite           | `http://localhost:5173`                    |

### حالت A — توسعه لوکال (بدون Docker، پیش‌فرض)

دیتابیس Postgres روی `localhost:5432` سیستم خودتان:

```bash
# 1) یک‌بار، در Postgres:
#    CREATE DATABASE techflow OWNER <user>;

# 2) تنظیمات (env مرکزی در ریشه؛ backend/.env اولویت بالاتر دارد)
cp .env.example .env        # و مقادیر DB/رمز ادمین را مطابق سیستم خود تنظیم کنید
cd backend
python -m venv .venv && .venv/bin/pip install -r requirements.txt

# 3) مهاجرت + ادمین پیش‌فرض (سازمان/تیم پیش‌فرض را هم می‌سازد)
.venv/bin/python manage.py migrate
.venv/bin/python manage.py create_admin
#    ← کاربر admin با رمز از TECHFLOW_ADMIN_PASSWORD؛ اگر خالی باشد رمز قوی
#    تولید و یک‌بار چاپ می‌شود.
#    (اختیاری) .venv/bin/python manage.py seed_demo   # دیتای نمایشی

# 4) اجرا
.venv/bin/python manage.py runserver          # بک‌اند
cd ../frontend && npm install && npm run dev  # فرانت (ترمینال جدا)
```

### حالت B — Docker Compose (راه‌اندازی سرور)

همه‌ی مقادیر پیکربندی از فایل `.env` مرکزی در ریشه‌ی مخزن خوانده می‌شود:

```bash
cp .env.example .env
# در .env تنظیمات ضروری:
#   TECHFLOW_SECRET_KEY    — حتماً مقدار قوی و یکتا
#   TECHFLOW_DEBUG=0
#   TECHFLOW_ALLOWED_HOSTS — دامنه/آیپی سرور (و backend برای پراکسی فرانت)
#   TECHFLOW_CSRF_TRUSTED_ORIGINS — origin فرانت، مثل http://سرور:5173
#   TECHFLOW_ADMIN_PASSWORD      — (اختیاری) اگر خالی باشد تولید و چاپ می‌شود

docker compose up -d --build
# در اولین بالا آمدن: migrate → create_admin (سازمان/تیم/ادمین) → runserver
# دیتا demo بارگذاری نمی‌شود (دیتابیس خالی شروع می‌شود)؛
# فقط در صورت نیاز: TECHFLOW_SEED_DEMO=1
docker compose logs backend | grep Password   # اگر رمز ادمین تولید شده باشد
```

- UI: `http://<سرور>:5173` — Swagger: `http://<سرور>:8000/api/docs/`
- با کاربر `admin` وارد شوید؛ از مسیر `POST /api/members/create/` (یا Django
  admin در `:8000/admin`) می‌توانید معاون، مدیر تیم و سایر کاربران را با نقش
  دلخواه بسازید و همه‌ی entity ها (تیم، پروژه، وظیفه، ...) را مدیریت کنید.
- دیتابیس روی `pgdata` volume ماندگار است؛ برای reset کامل:
  `docker compose down -v && docker compose up -d --build`

### ثبت‌نام (Signup)

- صفحه‌ی ورود تب «ثبت‌نام» دارد؛ حساب جدید به‌صورت **توسعه‌دهنده** در اولین تیم ثبت می‌شود.
- API: `POST /api/auth/register/` (آپارات: `username, password, full_name, email`) و
  `GET /api/auth/csrf/` برای بوت‌استراپ کوکی CSRF.

## مستندات API (Swagger)

- **Swagger UI**: `http://localhost:8000/api/docs/` (در حالت Docker: `:8000` روی هاست کانتینر)
- **شمای OpenAPI (YAML)**: `http://localhost:8000/api/schema/`
- با `drf-spectacular` تولید می‌شود؛ هر endpoint ورودی/خروجی تپه‌گذاری‌شده دارد.
  اسست‌های Swagger UI به‌صورت local (با drf-spectacular-sidecar) سرو می‌شوند، یعنی نیازی به CDN ندارند.
- برای تولید اسکوپ فایل: `.venv/bin/python manage.py spectacular --file schema.yml`

## حساب‌ها

- **ادمین پیش‌فرض**: `admin` توسط `create_admin` ساخته می‌شود؛ رمز از
  `TECHFLOW_ADMIN_PASSWORD` در `.env` (در غیر این صورت تولید و چاپ می‌شود).
- **حساب‌های demo** (فقط بعد از `seed_demo` — رمز همه `techflow123`):

| کاربر          | نقش          | پیشخوان           |
| -------------- | ------------ | ----------------- |
| `deputy`       | معاون فناوری | نمای مدیریتی کلان |
| `manager`      | مدیر تیم     | کاکپیت تیم        |
| `scrum`        | اسکرم مستر   | کاکپیت عملیاتی    |
| `ali` / `reza` | توسعه‌دهنده  | کارهای من         |
